# 验收

## 四边完整性：先通过，再评动效

按 [源素材与包装边界检查](framing-and-bounds.md) 分别检查源像素、媒体适配、容器遮罩、三维投影和前景遮挡，不以“卡片在画面内”作为完整性结论。

- 在原始分辨率看源文件四边。原片已缺失的 Logo、导航图标和文字必须识别并处理，不能直接带入包装后判通过。
- 每个镜头明确整窗或特写范围。整窗的必要边缘、四角及内部关键内容完整；特写不留下半字、半图标或无用途的侧栏残片。
- 检查运动中最大放大、最大倾斜、回弹极值及交接，确认相机和卡片各自运动时都安全；不能只验首尾静帧。
- 内部圆角、`overflow`、裁切/留边、字幕遮挡层和前景卡片都不能盖住必读信息。尤其不能为移走原字幕而盖掉菜单底部、输入框或按钮。
- 记录源边缘对照、输出边缘细节、问题层级及修正后的连续帧。技术 `validate`/`qa` 不检查语义缺边，不能代替本项。

发现这类问题应先修取景、媒体适配和轨迹，复查后再继续；不以强三维效果为理由容忍误裁，也不靠取消所有运镜规避检查。

## 实机主线与辅助演示

- 按 [录屏、截图与交互演示](recording-to-ui.md) 检查优先级：先包装实机录屏，其次选清晰截图，最后才为具体价值点或核心交互搭建短段演示。低清或失效裁切没有被强行放大，也没有导致整片改成 UI 搭建。
- 实机操作、实际反馈和真实结果仍构成主线。搭建片段有明确用途且回到实机；不能只因搭建更精致就持续替代录屏。
- 使用虚化录屏背景时，当前场景仍可定位，前景与底层状态对应；关键动作和字幕没有被模糊或遮挡，背景与前景的清晰度层次明确。
- 原生重建使用清晰文字与组件，字阶、间距、图标、圆角、透明度和控件比例符合产品风格；给模糊截图套边框不算完成。
- 同时只有一个主要阅读中心；全局与特写的共存有定位作用且及时完成交接，没有长期重叠的界面、重复字幕和半截句子。
- 重建范围与源文件/时间段可追溯，产品文案、状态、数值和操作因果经过核验；结果素材没有被“美化”成虚构产出。
- 先确认可读性和操作清楚，再检查 3D。若空间效果放大了源画面缺陷，回到呈现方式重新设计，不能仅调整滤镜、缩放或阴影后通过。

## 剪辑

- 当前讲述有对应操作或结果；没有与卖点无关的填充镜头。
- 重要控件可见、输入可读，结果有观察时间。等待读取过程可以压缩，但事实不能改写。
- 对比条件一致、当前版本明确；最后一个镜头有完成感。

## 设计与动效

- 默认包装背景为中性黑底，局部柔化彩光有实际的缓慢变化；合成后没有整体暗绿偏色、抢字炫光或模糊光层硬切边。实机与案例的原色不被统一调色覆盖。
- 标题、操作标签、说明有不同职责；检查中文字形、标点、断行、字距和安全边距。
- 看进入、中段、落位、退出；标题不能在重排时撞上控件。
- 点击指针命中实际目标；参考标签与被绑定位置对应；容器、标签和内容使用同一坐标依据。
- 主动作清楚；辅助动作更弱。不要让所有元素同时晃动。
- 立体上下文不会被父级 opacity/filter 压平；文字不贴在难读的透视面上。
- 摄影机与素材有独立关键帧，主要段落有主动的景别/空间变化。近远层的视差、尺度与遮挡关系可信，不能只把整张画面一起缩放。
- 关键操作落点稳定；相机移动时，指针、高亮、标签和绑定位置跟随同一个对象。含边框、内边距、裁切的素材先换算实际内容区，不用猜测坐标补偿。
- 视频进入三维面板后仍在正确时间显示正确源帧。核对源起点、场景起止、变速和解码等待，避免素材冻结或错帧。
- 纸感避免整体泛黄；卡通避免笨重硬框；复古避免旧系统皮肤；极简避免无信息的大空白。

## 反 PPT 动效自检

这是四边完整性通过后、正式导出前必须完成的一层检查，覆盖主要包装镜头、截图讲解和关键交接。先正常速度连看，再抽查运动前、中、落位与交接帧；不能只看首尾海报，也不能用关键帧数量、三维 CSS 属性或“高级感”描述替代证据。

| 检查项 | 通过依据 | 未通过时修正 |
|---|---|---|
| 摄影机是不是在调度视线 | 能指出观看目标、空间路线和落点，近远层的视差、尺度或遮挡随机位变化 | 重做独立相机位置/目标轨道；仅整屏缩放、卡片静态倾斜、切页或几乎不可见的漂移不通过 |
| 卡片/窗口自身有没有动作 | 能指出独立于相机的抽取、错层、旋转落位、展开、重排、归位等空间或结构变化 | 补足素材自身关键帧与因果；只有淡入、换字变色、片内视频播放、持续静置或被相机整体带动不通过 |
| 截图高亮有没有引导过程 | 目标准确，高亮建立、移动/变化和回收与讲解同步，视线按重点接力 | 重做相机与高亮的先后、目标绑定和阅读停留；只有静态框、文字依次弹出不通过 |
| 连续镜头是否仍像翻页 | 相邻段落有可追踪的对象、方向、位置或操作因果交接 | 重做交接；连续使用标题加静图、统一卡片飞入或“旧页消失/新页出现”不通过 |
| 立体效果是否真的可见 | 正常播放和实际观看尺寸下能分辨前后距离与相对运动，而非只看见阴影或描边 | 调整层间距离、视角和路线；不能用更强光斑或更重阴影代替空间关系 |
| 是否仍是清楚的实机教程 | 原操作与结果可辨认，字幕可读，动作后有稳定落点，UI 搭建仍只作短段辅助 | 减少竞争动作、恢复实机上下文、修正裁切与字幕；不能为摆脱 PPT 感而牺牲信息或真实结果 |

判不清时，可在检查副本中临时冻结相机轨道观察卡片动作，或临时冻结源视频播放观察包装动作；这些只用于区分贡献，不写入成片。源视频自己在动不等于包装已经有运镜。对于纯实机跟做或结果观察段，稳定观看是有意安排，不因静止就判成 PPT；检查的是包装镜头和交接是否只剩页面替换。

在现有审片记录中写明镜头/时间段、相机路线、卡片动作、高亮目标（适用时）、连续预览或关键帧位置、结论和修复项。确不适用的项目简述原因，不能把所有动作都标为不适用来逃避默认要求。发现以上问题，修正对应轨道并复查该段及相邻交接后再导出；未实际检查的部分保留为待验证，不能宣称已通过。

## 声音

- 配音清楚，切点无突兀断词；音效与可见动作对齐，完成音效有对应状态变化。
- 不连续堆点击、叮声和转场声。音乐是可选输入，默认不添加。
- 检查静音观看能否看懂，单听音轨能否理解逻辑。最终峰值与听感都要检查。

## 导出

`qa` 给出时长、流信息、黑帧/冻结候选和音量报告。正常静止阅读画面可能被标为 freeze，不能据此自动删镜头。背景黑色也可能被标为 black，必须回看上下文。

检查代表性帧和完整视频：色带、波纹、闪烁、缺帧、裁切、透明边缘、帧率、字幕、首尾和声音。使用草稿/预览验证内容，再输出正式码率；不因为 preview 成功而跳过正式导出复核。

若主要段落仍是同一种标题加平铺卡片、原录屏加矩形放大副本，或动效只剩淡入和小幅缩放，应重做镜头/对象关系；加更多装饰、光斑和转场声不能算修复。UI 重建还要看连续的输入、选择、反馈与交接，静态排版检查不能替代交互验收。

## 独立使用检查

- 本项目仅加载这个 Skill 和它的包内资源，不加载其他 Skill。
- 没有引用开发者机器上的私人脚本、账号、素材或硬编码绝对路径。
- 使用基础工具和公开软件依赖；用户材料仅在本次项目中使用。
- 记录实际验证过的内容，不承诺未经测试的首版满意率。

## 新增音频与录制验收

- Flova 音频项目与被演示项目隔离，复用实际项目/对话 ID；模型与输入限制来自当前能力目录，旁白默认 Seed Audio 1.0 多模态，参考条件下模型输入仅含朗读正文。
- 博主参考实际试听过，截取干净完整话语；无听觉验证不冒充已分析。旁白无漏字/重字/错误产品名，分段声音连续；下载成功且音频流有效后才加入计划。
- 配乐只在用户要求时加入，可由 Flova 生成；旁白、BGM、音效独立，实际试听音乐是否抢词与片尾是否突然。
- 页面录制只含授权标签页内容区，多个会话互不串录/互不暂停，暂停等待未进入导出的片段；用户手动暂停不会被活动自动解除。
- 对后台录屏检查真实内容重绘、画面帧率、空闲策略和阅读停留；技术并发测试不等于实际 Flova 项目的后台帧率已验收。
- 关闭页/浏览器重启能找到已写入的中断片段；未保存尾段、磁盘配额与编码错误明确报告，不假称完整恢复。

## Flova 内容指导验收

- 核心价值来自包内产品知识与当次材料，观众能看懂本次 Agent 提供什么帮助、实际如何操作、得到什么结果；没有堆功能名。
- 新版本、免费/积分/会员、模型与导出范围单独核对，不把旧 Brief 当作永远最新的全量公告。
- 没把方案/草稿/资产库入口冒充生成/保存/导出完成；多版本能力没有被窄化为某次角色数、图片数或秒数。

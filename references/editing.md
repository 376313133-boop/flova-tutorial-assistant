# 剪辑判断

先确定观众完成观看后能做什么，再选择镜头。一个语义段有一个主要任务：理解价值、找到对象、看清操作、确认反馈、观察结果或完成比较。

## 常用内容路线

| 路线 | 顺序选择 | 保留什么 | 最常见错误 |
|---|---|---|---|
| 跟做教程 | 目标/材料→必要步骤→反馈→结果 | 控件位置、输入内容、执行前后状态 | 切得太快，观众不知道在哪里点 |
| 结果拆解 | 成果→关键原因→对应操作→再次看成果 | 真实结果、影响结果的关键选择 | 好看的空镜与功能无关 |
| 比较选择 | 保持相同条件→展示差异→选中→用途 | 未选版本、当前版本标记、选择依据 | 数量与模型名称替代了用户价值 |
| 出镜讲解 | 人物建立问题→录屏证明→案例观察→人物收束 | 口型/声音连续、关键证据的完整性 | 人物一直占大面积，UI 太小 |
| 快速功能示范 | 明确标题→简短提问→精简分析/执行→真实案例 | 一个清楚的输入与一个对应结果 | 堆文字，反馈像宣传口号 |

路线可以在同一视频里切换，不等于五套固定模板。

## 时序与切点

- 配音实际时间是主锚点，脚本用于理解语义。提供逐句时间或 SRT 时先核对音频，不根据字数平均分配。
- 删除重复准备、无信息等待和口误，但保留让观众寻找对象、观察反馈的停顿。长生成等待可压缩并标明等待已缩短。
- 点击之前先让观众找到目标；点击之后给实际状态变化和结果时间。输入过程根据重要性选择实速、加速或只保留关键内容。
- 有前后对比时保持主体、比例与观察条件；版本选择要看到选中状态，不把所有候选直接删掉。
- 收尾要有稳定结果或下一步用途，不在动作未完成时截断。

## 画面选择

实机录屏是教程主体，案例承担效果证据，图解承担机制说明，人物承担讲述。截图用于稳定阅读，搭建的 UI 只辅助解释具体价值点或快速展示核心交互，不能取代实机主线或作为新增产品事实的证据。

先按 [录屏、截图与交互演示](recording-to-ui.md) 选择：录屏包装优先，其次清晰截图，最后才是短段搭建演示。低清、裁断文字、界面重排或字幕干扰使提取失效时，先调整剪辑与取帧；不能机械升级为纯 UI 搭建，也不能为了保留一块录屏而破坏阅读秩序。

避免连续重复同一种缩略图板式。需要空间感时通过对象遮挡、分层、局部到全局的变化建立关系；全画面持续微缩放不能替代运镜。

## 返修

把意见转成可定位修改：哪一个片段、哪一个对象、什么时间、改成什么可见结果。保存原计划版本，修改相关片段与声音事件；素材没变时复用 probe 和片段缓存。

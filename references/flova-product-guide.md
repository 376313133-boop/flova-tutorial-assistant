# Flova 产品知识与教程内容指导

本 Skill 同时负责教程内容判断与剪辑包装。先理解创作者想完成的事，再选择 Flova 能承担的工作、需要拍到的操作和能证明价值的结果；不能把“精通产品”写成一句角色设定后仍只处理画面。

## 知识来源与适用范围

这份知识于 **2026-10-21** 根据用户指定的《Flova 1.5 达人合作 Brief｜新》整理。原文页面显示最近修改为 2026-10-20，当前推广版本明确为 **Flova 1.5**。这里只提炼产品用法与演示原则，不分发原始案例图片、私人创作方法、完整合作文档或其内部选题库。

原始出处：[用户提供的 Flova 1.5 Brief](https://flova-team.feishu.cn/docx/Joo7dy9lgoHUzKxpo9ccyDvGnSc)。这是带日期的内容依据，不是所有账号、模型、地区和会员方案的实时能力承诺。执行前以当次真实界面、账号模型目录和已生成资源核验；后续材料出现新版本时更新判断，不把 1.5 固化为永久最新，也不沿用旧视频误写成 2.0。

## 产品到底帮创作者做什么

Flova 是围绕项目开展 AI 视频创作的工作台与创作 Agent：既能从想法走向作品，也能从已有剧本、参考图、音频或素材接手某个环节。创作者提出目标、提供依据并确认关键选择，Agent 理解上下文、组织方法与素材、安排制作，再把结果留在项目中供继续修改与复用。

理解它的价值要同时看三件事：**创作更自由、过程可控、方法与资产可复用**。不是只讲“一句话生成”，也不是把生成按钮数量当作全部升级。AI 完成了什么、创作者决定了什么，要在教程里分清楚。

## 功能、玩法与价值地图

| 产品能力 | 创作者能得到什么 | 怎样演示才成立 | 注意边界 |
|---|---|---|---|
| 理解项目并规划创作 | 从笼统目标发展出有依据的故事、视觉、表演与制作步骤 | 给一个真实目标和少量参考，展示它怎样理解材料、给出路线、保存确认的方向 | 创意提案只是方案，不能当作成片或成功率提升证明 |
| 主动检查与创作诊断 | 找出参考遗漏、版本冲突、表演或画面问题，减少盲目试错 | 显示有问题的真实结果、对应要求与诊断，再展示针对性修改和实际后果 | 不能仅凭 Agent 自述判定“已修好”，也不承诺每次都诊断准确 |
| 项目记忆与规则 | 先前确认的要求可作为后续创作依据 | 将明确要求保存为项目规则，后续任务展示如何读取并沿用 | 项目资料共享不等于每条对话全文互相共享，也不等于模型永久记忆 |
| 方法/Skill 组合与沉淀 | 延续原有习惯，为剧本、美术、表演等环节选择合适方法；跑通的方法可供下次复用 | 读取创作者指定的可用 Skill/方法，说明各自负责什么；查看项目工作文档与保存后的真实条目 | 项目里改了方法文档不等于已注册为个人 Skill；实际调用/保存以该账号入口和完成结果为准 |
| 项目内多对话 | 互不依赖的任务、集数或灵感可分别推进，并保留各自讨论 | 同一项目开两条有明确分工的对话，读取共同背景，切回原会话继续当前方案 | 不等于多个独立项目或无限并发；共享资料的并行写入仍可能冲突 |
| 批量准备与多版本生成 | 一起准备提示词与参考，集中比较候选，选定版本继续修改 | 先看一个可读草稿及其引用，再展示一批真实草稿的不同内容与状态，最后进行候选比较和版本选中 | **重点是素材多版本生成与管理**，不是“四个角色、两种模型、20张图”等某个案例数字；返回张数不等于提交次数 |
| 关联内容更新 | 修改指定对象后，让受影响的设定、分镜和制作依据保持一致 | 展示变更对象、关联范围与同步结果，并用无关人物/空镜作为对照 | 文档或草稿已更新不代表所有视频已重新生成；明确区分资料同步、任务准备、实际新结果 |
| 素材组织、检索与视图 | 大量素材有归属、找得回，候选能并排比较并继续使用 | 分类归组、名称整理、搜索定位，按需切列表/宫格/画布，再把选中对象加到对话 | 三种视图组织同批内容，不是反复复制三份；清理/删除前明确实际处理范围 |
| 资产库与跨项目复用 | 角色、场景、声音、方法和项目规则可整理为后续创作的起点 | 整理成独立分组，保存到资产库，核对完成，再在新项目引用/导入并继续使用 | 看到“保存到资产库”按钮不等于保存成功；引用、导入、整包复制不是同一操作 |
| 多剪辑方案与后期交付 | 一批素材可组织成不同节奏、长度的作品方案，保留各版供交付 | 创建/查看独立剪辑时间线，调整其中一版，再展示另一版仍存在及实际导出文件 | 不能把时间线草稿冒充已渲染成片；剪映/FCP/Premiere 等工程导出按当次版本与实际文件核验，不承诺任意软件无损互通 |
| 自由起点与单点任务 | 可以只做当前缺的一镜、先探索视觉、后补故事，或接着已有材料继续 | 提供现有脚本与角色参考，明确只制作指定镜头，检查前后文被理解且没有多做其他环节 | 示例中的 5 秒、720p 或固定角色不是功能定义；时长和规格由当次目标与模型支持决定 |
| 生成前检查与人机分工 | 方向不确定时先审草稿，明确后交给 Agent 执行 | 检查确认模式、提示词、参考及本轮范围，再发起实际生成 | 不等于零误操作、零消耗、永不跑偏；当前账号是否提供某模式须看界面 |
| 外部 Agent / CLI | 可以让常用 Agent 协助项目创作和资源交付 | 展示正式 CLI 对同一项目的请求、反馈、实际资源与交付 | 它是连接方式，不应自动包装成当前版本首创；调用流程不等于产品所有 UI 都能自动控制 |

### 角色、场景、音频、草稿、版本之间的关系

项目保存创作资料与素材；对话提出任务并留下各自讨论。提示词草稿组织本轮生成条件与参考，生成任务产生具体候选资源；选中一个版本后，再让后续任务沿用它。剪辑时间线组织选好的资源形成作品方案，导出才产生对应交付文件。**讨论 → 草稿 → 生成中 → 候选 → 选中版本 → 剪辑方案 → 已导出**必须按真实阶段讲，不能把这些状态都包装成“完成”。

## 常见需求怎样带着用户做

- **从零做作品**：说清受众/用途与目标 → 提供内容或参考 → 选择/调整方向 → 准备必要角色、场景与草稿 → 审核后生成 → 比较选定版本 → 剪辑、检查、交付。按实际项目跳过不必要环节，不要求固定故事板起手。
- **已有脚本或参考，只缺一部分**：列出已有材料和本轮边界 → 明确要做/修改的对象 → 引用对应资料 → 先确认 Agent 读对上下文 → 只推进所需任务 → 查看真实结果。
- **素材多、版本乱**：先识别归属与用途 → 明确整理范围 → 分组和规范命名、保留候选 → 搜索/视图比较 → 选中版本并继续使用。不要为了整洁擅自删未定稿素材。
- **做系列或品牌内容**：整理已确认的形象、声音、方法与规则 → 区分可复用核心与本集特有内容 → 验证保存与新项目引用/导入 → 用新任务证明它确实能接着用。
- **赶多项任务**：识别真正独立的任务 → 分会话但共用已保存背景 → 明确每条会话范围与输出 → 完成后汇合。存在依赖的任务先后推进，不为“并行感”抢跑依赖未确定的生成。

具体按钮名称、入口位置和可选模型从当次界面读取。知识库用于判断路线，不替代实机确认，也不提供凭空猜测的点击坐标。

## 把功能变成教程，而不是堆卖点

起稿前回答：观众为什么想看、看完能学会什么、本次任务 Flova 的关键帮助是什么。围绕一个观众目标组织主线，可以组合相关能力，不按产品功能列表机械朗读。

短功能说明可用：**讲准价值的标题 → 一句话需求/提示词 → Agent 分析与计划的极简摘要 → 真实操作/案例高亮 → 可观察结果**。这是信息组织建议，不是固定场景模板、统一镜头数量或必须每段 30 秒；完整教程可以先出成果，再进入实际跟做。创作者已批准的结构和个人表达优先保留。

例如讲批量能力，标题表达“素材多版本生成与管理”；镜头里再用当次真实的角色、场景或视频草稿说明玩法。字幕里不要把“20张”“5秒”“两个模型”放成产品能力上限或核心承诺。讲资产复用时说明留下了哪些东西、下一次怎么继续用；不能只展示一堆文件图标。

每个核心判断都配一条证据链：用户提供什么 → Agent 实际分析/执行什么 → 对象、草稿或结果发生什么变化 → 对创作者有什么用。Agent 的文字解释可以精简高亮，但不能虚构生成结果、夸大速度，或为了好看改变原始数据。

## 表述检查与更新

- 正在讲当前版本升级时，区分已有基础与新增组织/协作体验，不把 Skill、资产库、生成、剪辑等既有能力一概说成首次上线。
- “无限免费”“会员对话不扣积分”、会员权益、具体模型、分辨率、并发规模和价格属于易变信息，发布前单独核对当下官方口径与账号；Brief 中的标题或挑战选题不是已测上限和普遍承诺。
- 不承诺 Agent 智商提升比例、永久不忘、任意 Skill 无障碍迁移、绝不出错或一键适配所有平台。用案例中实际发生的帮助表达价值。
- 资料与界面冲突时，先识别版本、账号和展示状态；更新本次项目的事实记录，缺证据的部分明确待核实。用户提供新 Brief 时按相关能力更新此知识，不自动把私人案例与完整内部材料加入公开包。
